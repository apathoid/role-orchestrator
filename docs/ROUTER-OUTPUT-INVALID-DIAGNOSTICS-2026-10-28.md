## Implementation

- `src/routing/output-failures.mjs`: single strict allowlist of outer-schema error codes. Free-text and provider messages cannot be accepted as telemetry values.
- `src/schemas.mjs`: preserve the same strict validation and attach a separate stable code at its existing rejection sites. No schema or permission rule is relaxed.
- `src/structured-output.mjs`: carry `outputFailureCode` while keeping `ROUTER_OUTPUT_INVALID` as the backward-compatible general code.
- `src/workflow.mjs`: carry the code into `semantic_intent_validation` on contract failure. Fail closed: no route or Change without a valid Typed Task.
- `src/observability/execution-observer.mjs`: safe projection of the new field on both `router_output_diagnostic` and `semantic_intent_validation`.
- `src/routing/reporting.mjs`: expose `distributions.outputValidationReasons` on `/routing report`; old traces without the field continue to produce `{}`.
- `src/roles.mjs`: explicitly list all outer enum values and disallow extra outer keys; optional `title` retains its existing 120-character cap.
- `test/router-contract-reliability.mjs`: seven outer schema failures, malicious diagnostic strings, no-Change execution, trace and report propagation.

**The main failure code remains `ROUTER_OUTPUT_INVALID`**, so existing consumers are compatible. New `outputFailureCode` values are: `invalid_routing_root`, `invalid_routing_mode`, `invalid_routing_write_intent`, `invalid_routing_complexity`, `invalid_routing_risk`, `invalid_routing_reason`, `invalid_routing_title`, `invalid_routing_extra_fields`.
