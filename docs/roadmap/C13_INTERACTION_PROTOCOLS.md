**План для исполнителя.** Base: master merge PR #2, `50cffa4f0ab4151871beb36529be27e33f2c1d11`. Ветка `feature/interactive-ux`. Статус и следующий шаг — [STATUS](STATUS.md). **Неизменяемые ограничения всех шагов:**
- Модель владеет планом, выбором ролей/профилей/effort/tools, native tools и skills, вопросами, сообщениями, findings, оценкой качества и достаточности; Host только технической координацией. Direct Controller, параллельные Workers, waitPolicy, voluntary context retrieval и текущая независимость Workers при ошибке Controller сохраняются. Не добавлять reporting prompts/tools, новые модельные turns, mandatory roles, workflow, host semantic checks/keyword extraction, JSON repair/heuristics, host compaction, freshness gate, второй scheduler/lifecycle/ledger.
- Нативные AGENTS.md, skill discovery, файлы, terminal, scripts, provider subagents, VCS и права среды остаются собственностью нативного исполнителя. Никаких OS/FS/host isolation, chroot, namespaces, containers, COW, виртуальных workspace, protected readers, git root/HEAD/clean-tree/source hash checks или новых identity gates. Не требовать stable native message/tool id для исполнения, не связывать допуск с версией workspace, моделью или ролью. Существующие trusted grants, explicit writeIntent, configured globs/bridge, permission options, state CAS и техническая correlation остаются; проверять только принадлежность конкретного transport request/resource/attempt, не расширять это до проверки идентичности среды/модели. Не изменять native permissions без явной конфигурации.
- Никакой зависимости core от ACP/CLI wire, Zed, Codex, OpenCode или UI. Native protocol particulars только adapters/hosts. Не навязывать новые client capabilities всем адаптерам, не скрывать реально доступные native возможности из-за отсутствия bridge.
- Сохранять execution parser, durable observations/evidence, unknown effects, late outcome, dedup, cancellation provenance и teardown F0–F3. Activity не повышает trust, не становится автоматически evidence/Action/Decision/Finding и не запускает Controller. Не публиковать structured internal decisions как user text. Не восстанавливать пропущенные lifecycle events.
- Не создавать новый durable event store, replay log, фонового daemon, универсального RPC dispatcher или forms framework. Не предполагать будущее расширение без доказанного случая; расширяемость через минимальные optional contracts. C13 не реализует renderer и не задаёт compact/detailed/debug в core.

### Границы потоков

| Контракт | Источник/владелец | Гарантия |
|---|---|---|
| Execution | текущий ProviderPort → Coordinator → StateStore | существующая модельная семантика, durable truth |
| Model Activity Stream | provider adapter → application subscription | дополнительные фактически предоставленные native events, bounded best effort |
| Execution Events | существующий coordinator/application event stream | фактические lifecycle notices, не новая истина |
| Interaction | существующие permission/clarification и transport-specific correlated request/reply | ответ только живому запросу, authority, deadline, cancellation |
| Presentation | C14 hosts/clients | потребитель этих источников; не влияет на execution |

## C13.1 — Model Activity Stream: минимальный независимый контракт

1. Расширить ProviderPort необязательным callback (предпочтительно рядом с observe, с типом JSDoc; имя `activity`), связываемым application при invocation. Выбрать минимальную существующую точку composition, не новый coordinator. Legacy adapters без callback и no subscribers работают прежним путём. Доверенная invocation привязка задаёт operationId/attemptId; payload не может переопределить источник. Роль/profile берутся из фактического route, если нужны потребителю, не обязательные новые идентификаторы.
2. Нейтральный envelope: operationId, attemptId, kind (reasoning, explicit user message, native tool activity, native plan, explicit live finding только при подтверждённом источнике), payload, локальный sequence в пределах источника/attempt, optional native stream/message/tool identity; при необходимости техническая source metadata. Точные имена/union описать в CONTRACTS по реализации. Сохранить исходные данные и тип; wire payload/opaque extensions только на adapter boundary, не вводить ACP types в core. Не нормализовать план/находку семантически. Не требовать id от провайдера, не смешивать разные attempts; если stream identity отсутствует, маркировать отсутствие, не придумывать семантические границы. Sequence — порядок получения, не глобальный causal order.
3. Application exposes scoped subscribe/unsubscribe (operation, по необходимости attempt), переиспользуя существующие transport/authority, с noop default. Подписчик получает только разрешённую область; не изобретать отдельный ACL. Не сериализовать activity автоматически в invocation context, state journal или diagnostic export. Не обещать replay; при отсутствии клиента/подписки не буферизовать всю историю. Уточнить какой callback synchronous enqueue, какой delivery async. Исключить await renderer в execution.
4. Использовать существующие Execution Events отдельно: actual lifecycle, accepted outcome/findings с исходной ссылкой и model provenance. Не генерировать Activity из Host lifecycle, не подменять finding raw reasoning. Не реконструировать историю при пропуске; существующий inspect возвращает текущее состояние при явном запросе.
**Приёмка:** legacy/no listener и throwing listener не меняют invocation; 2 параллельных attempts, отсутствующие/совпадающие native IDs, source attribution; unsubscribe/disconnect, scopes; injected IDs не позволяют перенаправить activity; без subscriber нет новых model calls/state writes; исходный result/observations совпадают на детерминированном fixture.

## C13.2 — Достоверная negotiation и ACP relay

1. Разделить raw advertised client capabilities (сохранить декларацию/metadata без потери), фактическую per-connection доступность transport routes, trusted authority. Внутреннему ACP initialize передавать только реально обслуживаемые возможности с корректной формой, без отбора по роли/профилю/model/task. Не обещать raw advertised unsupported extension; не объявлять native tools отсутствующими при отключённом client bridge. Не вводить semantic capability calculator. Сохранять существующий флаг --relay-client-tools для FS/terminal, grants, client MCP запрет, configured policy; не расширять доступ без отдельного согласования.
2. Generic ACP relay только в ACP adapter/Host boundary. Существующие специализированные FS/terminal/permission handlers приоритетны; не обходить их generic fallback. Использовать supported SDK mechanism; переносить unknown extension method/payload без смысловой интерпретации, когда реально можно безопасно маршрутизировать. Не проксировать session/new/load/prompt/cancel, initialize или другие административные вызовы как произвольные tool requests. Отсутствие маршрута/неподдерживаемый method даёт адресный protocol error, не ложный ACK. Нет статического списка возможностей на основе названий моделей; технические handlers и доступность протокола определяют negotiation.
3. Binding: внешний client connection/session ↔ operation ↔ активный Attempt ↔ внутренний provider session/request; request/resource translation только в известных protocol fields или документированном extension mapping. Не рекурсивно переписывать все sessionId и не доверять arbitrary payload routing. Native IDs могут совпадать у разных sessions; scope внутренний. Проверять существующую принадлежность ресурсов, не добавлять проверки cwd/VCS/fingerprint. Forward notifications только к соответствующему session/operation, не превращать их в requests; responses/error/cancel correlated exactly once.
4. On disconnect/cancel/timeout: no new forward, pending requests завершить по protocol, cleanup owned mappings/terminal по действующему контракту. Если dispatch мог произойти и ответ потерян — техническая неопределённость, не выдумывать effect none/permission approval или повторять; поздний ответ не возобновляет завершённую Attempt. Не объявлять обычный вопрос mutation: effect provenance относится к реально возможному внешнему эффекту. Сохранить F1/F2 ownership/teardown.
**Приёмка:** fixtures raw/negotiated/full unknown metadata, relay on/off, unsupported extension, request/notification/error roundtrip, two sessions/attempts overlapping IDs, wrong owner, cancel/disconnect, duplicate/late response, terminal lifecycle, permissions и FS regression. Проверить реальный SDK subprocess, не только mock.

## C13.3 — Native activity без изменения результата

1. ACP: отдельная ветвь обработки native thought chunks, plan/tool updates, явно отделимых сообщений/находок согласно .0; output parser и observations получают ровно те же execution inputs, что прежде. Удаление/замена synthetic thinking в Host — C14. Не сливать ambiguous agent_message chunks в user stream; сохранить существующую result selection, correction, output refs и dedup. Native tool_call/update pairs сохраняют исходный ID, при коллизии scope только transport. Не генерировать фиктивные tool calls для lifecycle.
2. CLI JSONL: передавать фактически объявленные нативные reasoning/tool/activity events в момент получения, не ждать exit для таких событий. Не менять выбор declared terminal result, stop/exit/usage, existing observation journal. Для недоступных видов no activity, а не inference. Не менять provider-native settings, permissions, tools, model prompts, skill discovery.
3. Findings: accepted Decision/Outcome findings остаются модельными записями с refs; live finding только явно предоставленное сообщение с declared semantics; не преобразовывать слова в finding, не подтверждать live content. При отсутствии надёжного public stream показывать только доступные native events + принятый итог в C14. Не добавлять обязательный model reporting schema.
**Приёмка:** одинаковые deterministic input/outputs before/after (Decision, Outcome, raw observations, refs/provenance, journal, dispatch, usage), absent IDs, multiple progress/final, interleaved tool/thought, invalid Decision correction, truncated output, cancellation/late observations, no double final, same activity payload once per source event. При real provider variability сравнивать контракт, не требовать одинаковых модельных решений.

## C13.4 — Interaction: технический контракт, корреляция, timeout

1. Переиспользовать существующие PermissionPort, Controller clarification, Host session binding. Минимальная общая структура только для реально отличающегося request/response/cancel: opaque request id, bound operation/attempt, native request identity при наличии, kind/payload/options, deadline, terminal reply/error. Не заменять PermissionPort новой authorization layer, не менять Decision clarification/answer/resume/waitPolicy. Clarification относится к Operation/Controller, не обязательно живому Attempt; native request — к живому connection/Attempt. Не превращать text question в permission, permission в generic response.
2. Native interaction через ACP relay с original payload/options; клиент отвечает согласно своему protocol. Для unsupported/non-interactive route — точный unavailable/cancelled/error, никакого guessed answer/approve, не запускать дополнительные models. Для программного потребителя минимальный интерфейс доставки/ответа; не требовать renderer. Не проектировать общую формы DSL; CLI adaptation .0 подтверждённых видов — C14.
3. Ownership: существующий trusted control/session scope + ровно один pending request owner/response; observer != answerer. Проверять operation/attempt/request binding, valid offered option, active status, existing auth; duplicate same response idempotent, conflicting/wrong/late response rejected, no dispatch. Cancel clears pending and releases listeners; disconnect no implicit global operation cancellation. Preserve actual cancellation provenance.
4. Каждый native pending request ограничен конечным timeout: использовать существующие monotonic Clock/deadline и invocation deadline (не позднее), конкретное addressable interaction timeout, cleanup; no response must not hang. Сохранить existing operation/invocation/provider hard deadlines и slot accounting. Не считать pending доказательством blocked execution. Не паузить обычные deadlines; active-time only если отдельный доказанный contract и согласованное изменение, не здесь. Не удерживать slot после подтверждённого detach и не освобождать раньше.
5. Вне prompt: routing test .0; сохранить активных Workers, result delivery и waitPolicy. Если клиент не принимает out-of-prompt request, завершить только этот request по контракту, не переносить ответ/уведомление в чужой prompt. Не переоткрывать старый attempt.
**Приёмка:** deterministic clock timeout, reply/cancel races, disconnect, unsupported, concurrent requests, duplicate/reconnect, permission approve/deny/revoke, clarification resume, Worker independent, slots/cleanup, lost reply unknown effect. Не блокировать independent Work из-за недоступного interaction другого Attempt.

## C13.5 — Bounded delivery и local control transport

1. Применить bounded per-subscriber queue (count+bytes, finite documented defaults/config only if needed) к activity и новым потребителям execution notices; проверить существующий events.js queueMicrotask/async backlog. FIFO per source, best-effort drop при overflow, coalesce только технически совместимых chunks одного источника при сохранении текста/границ, gap indicator с count/reason/sequence range если известно. Не реконструировать lifecycle, не сортировать по смысловой важности. Subscriber failure isolated, unsubscribe cleanup, no await on provider execution. Не добавлять persisted queue.
2. Разделить single wire frame limit (NDJSON), accumulated result/output/capture limits и activity delivery budget; activity объем не расходует result budget, существующие capture/diagnostic bounds сохраняются. Большой native frame может законно встретить protocol limit; не скрывать. Pending interaction/permission/terminal outcomes не drop молча и не зависят от best-effort queue: separate correlated path/authoritative existing state; terminal transport response или адресная delivery failure, inspect remains. Не менять evidence retention or payload contents for display.
3. Local control: расширить текущий owner endpoint (src/hosts/local-control.js, commands/composition) только для scoped subscribe/event delivery и answer pending interaction, если needed для CLI; сохранить existing version/requestId/token/configurationRef/owner, request dedup, single writer, startup/shutdown. Observer/answerer binding отдельно; no second daemon/store writer. Existing ACP owner accepts existing commands; не разрешать local run/resume ACP operations обходя соответствующую session. Не retry lost request with new id; disconnect closes subscription not execution; reconnect explicit pending inspection (доступный scoped metadata, no replay old activity). Если текущего транспорта достаточно, расширять минимально; public protocol fields documented, backward compatibility tests.
4. Redaction: existing diagnostic/export boundaries; raw activity not dumped to logs by default, secrets/token not exposed, explicit opt-in bodies only where current trusted policy allows. Activity transport to authorized recipient не требует семантического scrub произвольного model text; UI sanitization C14. Trace technical source/kind/size/drop/timeout/correlation without full prompts.
**Приёмка:** slow/throwing/no reader, unbounded stream load bounded memory/queue, oversized activity vs valid terminal, permission and final not silently lost, local control reconnect/duplicate/wrong token/owner, no extra dispatch, old commands and clean teardown.
