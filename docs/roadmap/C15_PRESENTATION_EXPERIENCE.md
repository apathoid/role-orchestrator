## 1. Цель и утверждённые решения

CLI должен стать удобным цветным streaming-интерфейсом со scrollback, различимыми источниками, нативными thinking/tools, понятными lifecycle/finding/interaction blocks и итоговой сводкой. Не полноэкранный TUI; **обновляемая строка состояния (live status line), persistent REPL, новые команды для постоянной chat-сессии вне C15**. Печатные статусы по событиям допустимы.

В графическом ACP-клиенте RO органично дополняет общий диалог фактами о собственной деятельности. **Inline progress — default сразу в C15**, а не эксперимент, требующий отдельного согласования или native acceptance для переключения. Нативный UI клиента (thinking, tool calls, dynamic plan, permissions, forms и прочие доступные элементы) остаётся нативным. RO не пытается воспроизвести GUI карточки, сворачивание, цвета или управление layout средствами фиктивных протокольных объектов. Стандартный ACP agent_message_chunk для собственных коротких сообщений RO; notices остаются явно выбираемой совместимой альтернативой, capability-gated. Одни и те же факты не дублировать в обоих каналах. Возможность отключения дополнительного progress — использовать existing equivalent или минимальный transport-only вариант, если необходим; не вводить множество настроек.

**План модели не изменять:** оставить текущие ACP native plan mapping, режимы и единственный Controller plan slot; не создавать Host-generated orchestration plan, не объединять Worker plans, не требовать планирования. Список запущенных Workers — факт исполнения, не новый план. Не изменять native thinking/tool/public message channels, не принуждать модель к live findings, не извлекать их из текста.

**ACP user transcript включает собственные информационные сообщения RO.** История существенных durable orchestration facts восстанавливается из существующего Operation journal с корректной последовательностью session.requests и связью каждого turn с первоначальным Request или operation.continued. Не обещать точный replay live UI, не персистировать raw thinking или всю activity ради интерфейса. Отсутствие доставки не означает отсутствие факта. История пользователя не является модельным контекстом, evidence или новым execution journal.

## C15.2 — CLI Rich Streaming Renderer

Цель — основное визуальное улучшение в обычном терминале. Пример иллюстративный (все названия/тексты должны приходить из реальных событий):

    Role Orchestrator · compact · operation 8f2d

    ● Controller #1 · Sol · medium
      Thinking
      Проверю восстановление структуры…

    ├─ Explorer #2 · Terra · high
    │  Анализ восстановления состояния
    └─ Reviewer #3 · Sol · high
       Анализ тестового покрытия

    ● Explorer #2
      Thinking…
      ◇ Read file · src/editor/history.js

    ◇ Recorded finding · Reviewer #3
      [model-authored claim; uncertainty if available]

    ✓ Reviewer #3 completed
    ● Controller #1 · Sol · medium
      Thinking…

    [исходный финальный ответ]
    ✓ Operation completed · 2 workers · 1 recorded finding

1. Trusted styling: аккуратные цвета, dim/italic, отступы, separators, читаемые source headers, accents errors/findings/questions/permissions. Сначала sanitization недоверенного content/labels/objectives/tool text, затем доверенные ANSI renderer; не выключать terminalText() глобально и не дать output sanitizer удалить доверенные styles. Не изменять persisted/provider text, machine JSON или redirected final stdout; ACP stdout protocol-only.
2. Incremental native thinking: соседние fragments того же фактического источника/stream продолжают блок; смена source/type, tool/finding/interaction/lifecycle создаёт визуальную границу. Не ждать полного reasoning, не анализировать текст, не придумывать завершение reasoning или native message boundaries; не смешивать Attempts/streams, не объединять по сходству текста. 3. Compact native tools видимы: actual title/kind/status и доступное описание/команда, status updates scoped IDs; большие tool bodies не печатать по умолчанию. Recorded не значит confirmed/accepted; не назначать severity, не суммировать model content в Host. Не извлекать из thinking. Safe bounded display больших bodies; inspect остаётся доступным.
