## D15 — Адаптивный reasoning effort (реализовано, regression verified; native UNVERIFIED)

Параметр нового модельного вызова расширяет существующие Profile/Action/Decision/Invocation/Attempt, не создаёт второго scheduler. Пользователь задаёт mapping общих имён в native values; Host проверяет выбор, adapter передаёт параметр. Конфигурация остаётся v1: отсутствие поля означает native.

Controller может явно продолжить самостоятельно и выбрать effort следующего хода без внешнего события. Специальные ограничения циклической смены уровня отложены до реальных наблюдений; обычные технические бюджеты остаются. Альтернатива «только worker effort» вынуждала бы делегирование ради настройки; требование внешнего события ограничивало бы полезное рассуждение на прежних данных.

Цена: больше вариантов модельного выбора и отсутствие гарантии оптимального расхода. Неподдерживаемый собственный effort показывается пользователю без скрытого fallback; это сохраняет явный выбор ценой возможного ручного продолжения. Acknowledgment остаётся атрибутированной информацией, не gate. Контракт и ограничения: [reasoning effort](REASONING_EFFORT.md).

Решение пересматривается только по конкретной потребности и доказательству, с обновлением затронутых контрактов и проверок. Увеличение числа переключателей, confidence thresholds, state machines и approval prompts само по себе не является повышением надёжности.

## D16 — Постоянная структура и сохранение инженерных знаний (реализована в C12.0)

D10/D14 — исторические решения, заменённые D16 при C12.0. Старый каталог доступен в истории Git, не является действующим источником. D11 сохраняет JavaScript ESM/JSDoc как независимый runtime-контракт.

D10/D14 решали реальную задачу: production не должен зависеть от тестов, временных отчётов, инженерных проверок и coding-agent prompts. `development/` обеспечивал эту границу физической сепарацией, но одновременно обособил активный план, тесты и опыт разработки. В C12.0 утверждён переход к размещению **по назначению**, при котором независимость продукта защищают архитектура зависимостей, npm/Nix packaging и проверка установленного экземпляра.

Целевое состояние: `tests/`, `scripts/`, `.agents/`, `docs/`, `docs/roadmap/` (активный план и STATUS), корневые `AGENTS.md`, `CHANGELOG.md`, `CONTRIBUTING.md`. Git хранит историю кластеров и отчётов; текущие продуктовые знания — в предметных docs, причины решений — в DECISIONS/ADR, продуктовые вехи — в CHANGELOG. Матрица R/A остаётся продуктовой; критерии миграции M01–M04 отдельно инженерные, не создают фиктивного runtime функционала.

Ранее отвергнутые Host isolation, обязательный Git/VCS consistency, fixed workflows, второй scheduler, автоматический replay unknown effects или Host judgment findings **не возвращаются** при переносе. Сохранены model-first, provider-owned tools, permissions, provenance, mutable workspace и отдельная native-приёмка. Исходный `development/` удалён после переноса текущих знаний, тестов и CI. Независимость установленного продукта проверяется `check:removal`, npm pack и Nix/CI; исходные тесты сохраняются в Git.

## Обязательные границы утверждений

Host способен гарантировать собственный порядок dispatch, уникальность id, соблюдение ресурса, который измеряет, и связь доверенного permission response с попыткой. Он не гарантирует корректность reasoning, поведение произвольного кода внутри провайдера или неизменность среды.

Отказ от файлового enforcement не разрешает модели игнорировать задачу и ограничения пользователя. Если нужна более сильная гарантия, выбирается соответствующий исполнитель/существующая инфраструктура пользователя; scope Role Orchestrator не расширяется автоматически.

## D17 — Стабилизация технической координации C12R

Локальный отказ Controller не является отменой ранее принятых независимых Actions. Сохраняются исходные admissions, зависимости, cancellation, authority и общий budget; существующее резервирование обслуживает технически готовые запросы FIFO без семантического приоритета. Альтернативы — глобальная остановка, автоматический fallback и отдельный scheduler — теряют полезную работу или дублируют модельные решения. Цена: ожидание доступных slots и сохранение pending/unknown evidence; незанятый ресурс нельзя объявлять свободным до подтверждённого detachment. Durable recovery использует тот же ledger и не повторяет неизвестный эффект.

Выбранный skill материализуется в один структурированный источник (доверенный inline либо loader) и включается в фактически отправленный Invocation и его request identity. Controller получает metadata, Worker — только выбранный skill. Локальный запрет native subagents не превращается в Host keyword gate. Альтернатива — объединить весь текст skills или всегда предпочитать loader — смешивает scope/версии и ухудшает identity. Неполнота отмечается явно; модель выбирает продолжение. Не меняется native discovery самого Controller.

Не вводить prompt compaction, дополнительный semantic workflow или обязательный quality score. Доказанные дефекты исправлены технически; дальнейшее изменение Controller instructions, effort или координационной стратегии оправдано только реальным comparative evidence, а не числом тестов/Workers. См. [execution](EXECUTION.md), [context and recovery](CONTEXT_AND_RECOVERY.md), [extensions](EXTENSIONS.md), [roadmap STATUS](roadmap/STATUS.md).


## D18 — C12R.9: доставка исходной истории вместо Host-компактизации

Решение: сохранить единственный Operation journal/ContextPort как source of truth, удалить доказанные duplicate **inline copies** по совпадающей технической идентичности и bytes, разделить бюджеты Controller/handoff/fetch/capture/skills/tools, отказаться от 128-record cap, дать модели компактную derived карту и добровольный `nextController.contextRequest` без MCP. Это позволяет не повторять expensive Workers при потере старой информации и не вводит parallel state/index, host importance ranking, mandatory reasoning turns, model-authored knowledge store или запрет provider-native tools. Отказ от более тяжёлого Host compaction обусловлен отсутствием доказанного native выигрыша; его нельзя незаметно включить позднее. Влияние на нативную качественную работу и стоимость должно оцениваться на настоящих моделях отдельно от PASS синтетических контрактных тестов.


### D19 — C12R.9 review: техническая адресуемость без индекса и семантической сортировки

Выбор: дедуплицировать только явно коррелированное финальное сообщение ProviderPort (и доказанные byte-identical provider observations), оставив оригиналы в journal. При ограничении prompt host показывает полные технические counts и omissions; ранее принятые Decisions позволяют модели выбрать `workCursor` или позиционный `ref`. Для последовательного чтения большого сохранённого тела используется byte-offset `ContextPort.fetch` с base64, SHA‑256/retention и действующим scoped authority; те же данные доступны через MCP и `nextController` без обязательных дополнительных toolkits. Никакого индексированного журнала, semantic ranking, Host-generated summary, нового filesystem runtime, фиксированного review workflow или автоматического retry unknown effect не требуется. Альтернатива простого увеличения 256 КиБ до 512 КиБ не гарантирует историю без потерь и оставлена только для native comparison.

### D20 — Бюджет ответа принадлежит получателю, но доступ к истории остаётся модельным

Технический `fetchMaxBytes` — общий верхний предел ContextPort, а MCP/Controller налагают независимый per-call output envelope budget; это не алгоритм relevance ranking и не изменение конфигурации под роль. Если следующий байтовый фрагмент не помещается, сохранить его byte-accurate offset важнее, чем передать необрабатываемую часть. Производная workMap-пагинация не предлагает пустую следующую страницу. StateStore может оптимизировать повторное чтение SHA-верифицированного artifаct временным кэшем, проверяя версию backing-файла и retention при каждом чтении; произвольные внешние StateStore сохраняют старый full-read fallback. Не создаётся второй persistent registry/index, automatic fetch или принудительный дополнительный turn.

### D21 — Stable workMap traversal without freezing lifecycle

`workCursor` is a `{revision,index}` position in a journal-prefix membership, not an offset in the moving live array. First Attempt inherits the accepted Action's admission position and admission-array order; later attempts retain their reservation order. The initial Controller is excluded using the same historical journal prefix. Current lifecycle/outcomes/refs remain live; `liveTotal` exposes new work, a fresh cursor 0 includes it. No persisted pagination snapshot, knowledge index, mandatory reconciliation or additional Controller turn. A legacy nonzero numeric cursor can still be decoded in v1 persisted Decisions but explicitly yields invalid_cursor: interpreting it on a different live array is unsafe. Accepted-only disposition is derived from existing execution events; rejected admission of a repeated proposal is not execution rejection. Deferred is not terminal. This preserves model ownership of retrieval, strategy and retry decisions.

### D22 — Stable history directory without a second index

The moving numeric offset in ContextPort.list could repeat or skip pages across new Controller invocations. Use the existing journal-prefix revision/index principle independently of workMap and positional fetch. Derive membership from the original prefix; late observations can update source metadata for the same ref without shifting other event-local positions. Ambiguous legacy output positions cannot select a different late body. Keep the exact structured page when applying recipient byte limits; advance by the delivered count only, and preserve end/error/budget in technical coverage. No persistent pagination state, new store, semantic ordering, required retrieval, Worker blocking or changed default budgets. A fresh cursor 0 includes new records; legacy nonzero numeric offsets explicitly reject rather than guess. Model chooses whether to retrieve, continue or finish.

### D23 — Activity and interaction are optional delivery contracts, not execution

Preserve native protocol semantics and original provider output; ambiguous agent_message content cannot be classified as public progress or finding. Optional activity is bound to the admitted attempt, independent from observations and model context. Bounded best-effort FIFO with explicit gaps avoids renderer-induced provider waits and unbounded backlog. Existing execution/terminal/permission paths remain authoritative and separately correlated. Native input uses the existing deadline and configured answer owner, not a second lifecycle or paused active-time accounting. ACP advertises only actual supported routes, preserving raw declarations separately; explicitly configured extensions cannot bypass permission/FS/terminal handlers. Local control extends the single owner with scoped notice subscription and an accepted-work answer binding. No reconstructed events, model reporting prompt/tool, semantic host checks, replay queue or environment identity gate. C14 may present only supported facts; actual native acceptance remains separate from subprocess tests.

### C14 decision: thin client consumers, no reconstructed thinking

Use common pure display mapping and existing C13 delivery, one terminal reader/owner, standard ACP updates with attempt-scoped native IDs. Mode does not affect execution or availability of input. No UI-specific scheduler, durable event store, proprietary ACP widget requirement or fake progress. Trade-off: absent native channels cannot be shown live; safe omission, explicit current snapshot/inspect in CLI and bounded gaps are preferable to guessing. Local control attached pending input is handler delivery, not new permission authority.

### C13R/C14R — reliability and negotiated notices
Reuse existing work request/token/answer binding for reconnect, never restart unknown work. Separate bounded normal presentation finish from immediate disconnect. Codex raw capture exhaustion is not a wire parser failure; retain bounded execution facts and latest result independently. Use pinned ACP SDK standard session.notices capability for actual committed findings/lifecycle/gap, not synthetic tool/thought or extra history. No new scheduler, native isolation, workspace gate, mandatory reporting or model semantics. [Corrective roadmap](roadmap/C13R_C14R_INTERACTION_RELIABILITY.md).


### C15 — Rich presentation and user transcript (implemented)

RO as the external ACP agent may emit its own compact attributed factual progress via standard agent_message_chunk. Inline is the agreed default from C15; capability-gated notices remain explicit compatibility mode, not duplicate delivery. Native client thinking/tools/permissions/forms and existing Controller plan behavior remain unchanged. Use existing session.requests order and exact initial Request/operation.continued association for transcript recovery, with minimal session turn metadata only where required; journal remains the execution authority. Durable facts may be recovered even if live delivery was absent; transient diagnostics and unpersisted native activity are not reconstructed. User transcript is not model context/evidence, and no second execution journal is introduced. Keep existing event publication/dispatch and bounded delivery independent of Coordinator. CLI adds trusted styles and technical streaming grouping, not live status line or REPL. ### C15R — presentation quality and fidelity

CLI owns a bounded, ephemeral projection of actual native tool identity/fields and current source blocks, not a second execution state. Append-only output, no status-line redraw or reasoning aggregation. Distinct compact/detailed/debug; native ACP updates remain untouched. Shared human TTY defers only the summary to authoritative stdout confirmation; machine output unchanged. Reuse the existing outcome resolution/classification and snapshot prefix ledger for history, not a second reducer or execution journal; missing classification explicit. Skill changed diagnosis remains separate and UNVERIFIED until direct native comparison. See [C15R](roadmap/C15R_PRESENTATION_QUALITY.md).


### C15R.6 — terminal question safety (engineering)

Reader captures request identity and registration epoch at start of a physical line, not its currently sole pending request at Enter. Display aliases are local and monotonic, but trusted owner/deadline/permission option IDs remain authoritative. Native forms are projected from the pinned restricted ACP form contract into a minimal per-request ephemeral field draft; no generic JSON-Schema engine, Host semantic relation inference or persistent question journal. A technical newline during an active readline redraw is not a source/Thinking boundary. CLI tool aliases are scoped only to delivered native identity, bounded entries/bytes and not used for effects. Partial ACP session history emits attributed own recovered notes for known orphan request records; never invents turn order or response. Alternatives rejected: raw JSON-only input, dynamic sole-pending line routing, fake form alternatives, replaying history or augmenting model prompts. See C15R.6 roadmap.

### C15R-UX-R2 — bounded technical CLI previews and visible native choices

A numeric option position in CLI is admitted only if its original label/scope was actually displayed for the live request/field; a per-request bounded list of displayed pages supports revisiting earlier choices. Exact `id:<optionId>` deliberately retains the existing explicit-ID selection, and trusted broker authority still decides grants. No new Host permission gate, scheduler or execution state is introduced. Alternative rejected: accepting any index from all available provider options, which can approve a wide-scope option never presented to the user; also rejected forcing every option into one unbounded output.

`:details` intentionally previews a finite, known set of technical native JSON fields using own property descriptors without running accessors. Unknown object keys are **not** enumerated, so a very wide object does not trigger proportional CPU/memory work merely to render an optional CLI preview. Alternative rejected: unbounded `for...in` or whole-object `JSON.stringify` (Node24 measured 43.14 ms, ~5.16 MB for 300k keys before vs 0.06 ms, ~3 KB after). Tradeoff: metadata outside the recognized set may be omitted; CLI discloses this and never changes the native request, permissions or typed form answer. No worker thread, new provider call or artificial environment. This protects UI resource use only for the ordinary decoded JSON-shaped native path; arbitrary hostile proxies and full native-provider UX remain outside the guaranteed boundary. See [R2 status](roadmap/STATUS.md).

This narrowly supersedes historical C14/C15 compact plan omission, without synthetic planning, required stages, Worker plan merging or extra Controller prompts. Original model Markdown and `Assessment.answer` must not be parsed/reassembled/altered.

Existing bounded transport, journal-based history, native tools, skills, permissions and independent Workers remain authoritative and unchanged. Rejected alternatives: Markdown AST/parser, fake tool/thought/plan widgets, Zed-specific execution/core, new UI state/journal, workflow/environment assumptions and extra semantic Host powers. The minimal ACP-only implementation and deterministic SDK tests are recorded in STATUS. Real Zed rendering and native performance remain UNVERIFIED. [Roadmap](roadmap/C15R_GUI_GRAPHICAL_ACP_PRESENTATION.md).

### C15R-GUI-R1 — single event set, separate ACP text contracts

Technical debug is a richer **projection of the same selected execution facts**, not a second full diagnostic transcript; inspect/trace/export still own raw diagnostic detail. Standard ACP `notice.title/description` are plain text and must not acquire Markdown escape characters; RO-own `agent_message_chunk` may escape a fixed trusted presentation template only. Original model content and durable findings are never parsed or modified; multiline values are displayed with continuation indentation so untrusted text cannot impersonate trusted field labels. Route-level model/effort wording states only requested provenance. The alternatives—generic Markdown parser, forwarding all debug diagnostics, markup escapes in plain notices and a new event/renderer lifecycle—are rejected as unnecessary and harmful. [Scope and evidence](roadmap/C15R_GUI_GRAPHICAL_ACP_PRESENTATION.md). Real Zed rendering remains UNVERIFIED.

### C15R-GUI-R2 — compact factual progress without a second renderer lifecycle

The existing ACP Host selects a smaller set of *its own* durable technical notices for compact: omit UUID-heavy accepted and routine known completed reports, preserve dispatch identity and unresolved/unknown/failure/late/cancellation facts, and omit assessment decoration only if the committed model Assessment has a nonempty answer. This is a read-only display predicate, **not** a Host judgement of success or provider effect. Detailed/debug remain truthful metadata views. Declining a synthetic native-tool/thought/plan or per-client grouping hack also preserves the standard ACP/client boundary. Reuse the same journal projection on live and `session/load`, do not add timing/grouping/buffering state, and keep native model-authored messages untouched. See [C15R-GUI roadmap](roadmap/C15R_GUI_GRAPHICAL_ACP_PRESENTATION.md) and [current engineering evidence](roadmap/STATUS.md). Actual Zed acceptance UNVERIFIED.


### D24 — C16: технические user-turn references и журнал как единственный счётчик Decision recovery

Решение: первоначальный Request и все последующие literal user turns остаются неизменными ContextItems с journal provenance; Controller получает только пары исходной/последней `ref + receivedSequence`, чтобы самостоятельно интерпретировать изменение задачи или уточнение. Замена `objective` по позиции, статусу или questionId отвергнута: это передало бы Host семантическое определение намерений. Новый индекс активной задачи и повторное хранение текста не нужны.

Rejected Decision сохраняет структурированную категорию фактической parser/decoder/admission boundary рядом с прежним FieldError. Пороги 5 подряд одинаковых и 10 суммарных отклонений выводятся из существующего журнала, включая проверку перед reservation после crash-gap, без второго persistence ledger или самостоятельного retry scheduler. На пороге используется существующее локальное Controller technical waiting с реальным attempt identity, а принятые независимые Workers и поздние outcome продолжаются. Повторные accepted Decisions и новые user turns изменяют только соответствующие технические счётчики, никогда не authority или общий maxInvocations. Альтернативы глобальной остановки, silent auto retry с новым бюджетом, Host-generated final Assessment, semantic error classifier и regex JSON repair отклонены. Text-only Decision v1 reference — отдельная экспериментальная часть: синтетическое принятие не доказывает качество реальных моделей, в том числе их native tool и delegation autonomy; необходима сравнительная native проверка C16.6. Steering активной операции не реализуется.

## C17 — Presentation, rejected-result addressability and passive observation

Separate literal Controller text sections from the Decision transport contract; keep native structured providers and Worker text untouched. Never infer current user intent, task strategy or tool inventory from a section. Reference a rejected declared result only with durable receipt provenance (or an explicit canonical declared-value fallback); preserve distinct wire/decoded representations and optional legacy event compatibility. No second result store, Host semantic compaction, forced retrieval/reuse, automatic new attempts or new workflow. The existing budgets and journal own recovery. Diagnostics measure actual rendered text separately from context/transport/provider usage, and capture is bounded opt-in private observation. Human compact summary suppresses a terminal decoration only on matching journal identity/status/source/reason; in-progress and non-equivalent outcomes remain visible. This is a presentation decision, not execution policy.

C17R refines this decision: explicit adapter-owned parsing provenance is optional; unknown raw/declared correlation falls back to the canonical declared value. Recovery uses existing measured common budget before default previews, retaining explicit model selections and original historical order. Configurable raw capture and actual serialized NDJSON limits are distinct; diagnostics remain passive. No new source of truth or model policy.

## D25 — C18: model-owned ControllerIntent and deferred, nonblocking transport (IMPLEMENTATION; NATIVE UNVERIFIED)

**Decision:** the Controller authors only semantic `ControllerIntent`; trusted Host binds `schemaVersion`, stable `decisionId`, invocation `operationId`/`contextCursor`, actual Controller-profile author and strictly defined empty-field defaults to the **unchanged canonical Decision v1**. One existing decoder/admission and Operation journal remain authoritative. Model keeps action/finding/requirement identities and all semantic fields. Explicit MCP `submit_decision` offers in-turn structural feedback but is *proposal-only* until a trusted native turn completion. Text/native structured paths use the same Intent where supported; legacy paths remain available.

**Finality:** one invocation-local candidate; unrelated submissions without explicit replacement cause a *recoverable* conflict. For **explicit parallel replacements of the same known lineage**, temporary **last-wins by trusted request registration order**, not asynchronous completion order; **no proposal CAS/versioning** at this stage. Observable invalid replacement invalidates prior candidate; missing/unobservable client-side MCP request is not invented. Pre-completion registered calls are resolved within bounded lifecycle before final admission; unresolved transport races are technical failures, not fabricated model schema errors. Cancellation/unknown/native failure cannot admit a pending proposal.

**Provenance/capacity:** generic invocation-scoped submission capability binds active Controller attempt, does not prove root native-agent authorship. Protect independent invocations without provider-name branches in Core. Ensure `submit_decision` works without context retrieval/external tool ports, and that old MCP request and tool-count limits do not arbitrarily exclude legitimate large Decisions. Resource limits remain bounded and transparent. Pending, invalid and conflicting proposals **never restrict unrelated provider-native tools, scripts, skills/subagents or model reasoning**.

**Rejected alternatives:** full technical Decision generated by model; Host semantic completion or regex repair; immediate Action execution from MCP calls; implicit last-wins for unrelated submissions; permanent conflict failure while native turn is active; extra `finalize` round; proposal-specific CAS/versioned system; second scheduler/persistent pending log; Host Git/freshness/review gates; root/subagent detection hacks; hidden provider retries after possible effects. **Tradeoff:** temporary explicit last-wins favors simplicity over protecting simultaneous intentional updates; root native authorship is not universally provable; input budgets and native performance require actual acceptance. See [C18 roadmap](roadmap/C18_CONTROLLER_INTENT_AND_DEFERRED_ADMISSION.md). This design has an opt-in feature-branch implementation; engineering exact-SHA and genuine native comparison determine its verified status. The stable attempt/content-derived decision ID is not proof of durable receipt idempotency.

### D25 / C18R — Technical observability is not semantic gating

C18R refines D25 with narrowly scoped transport ownership. ACP native-event capture may be incomplete while an independently received, invocation-scoped MCP Intent plus trusted `end_turn` is complete; only the former is marked truncated and cannot masquerade as complete original model text. An observed failed explicit replacement with known lineage invalidates the previous candidate rather than silently admitting it, but unreadable/unknown attempts do not. A reused request ID is a transport problem, not evidence of invalid model content. A deterministic collision-free builtin MCP tool alias preserves existing external tool accessibility without reserving the external ID or adding Core/provider-specific semantics. Decision receipt dedup additionally requires original Controller attempt provenance; ambiguous durable state is recovered by the existing journal/Worker rules, not a new proposal log or exactly-once claim.

## D26 — C18N: transient evidence index, advisory feedback and active-only ordinary MCP

**Decision:** expose existing accepted native observations directly as an invocation-borrowed, read-only `LiveEvidencePort`, with append-only per-invocation index cursor, scoped canonical ref and bounded byte fetch. A separate historical `ContextPort` retains its immutable journal-prefix traversal. The adapter advertises only negotiated tools and preserves all external names via built-in aliases. Do not create an alternate Observer, permanent discovery registry, semantic scoring, native inventory, second journal, source-file reader, workspace gate or required model retrieval. The model interprets and chooses evidence and tools.

**Preflight:** after synchronous structural registration of `ControllerIntent`, reuse `admitFindings`/assessment diagnostics on a **fresh copy** of historical plus current-invocation reference sets. The result is a bounded advisory snapshot, never a second admission, veto or proof of future validity. Same-turn explicit last-wins lineage and the original authoritative Operation admission/finality remain unchanged. Historical declared results are not previous-invocation `proposalRef` capabilities.

**MCP resource compromise:** drop the cumulative 64 ordinary-call count and release completed ordinary request args/Promise/results. Retain active same-ID correlation and reject incompatible **concurrent** requests. Late same-ID delivery after cleanup may execute again, explicitly not exactly-once for arbitrary external tools; no inference from tool effect/name/arguments and no automatic Host replay. Retain stronger same-invocation `submit_decision` identity and durable controller/Worker guarantees. The technical 128 control-call bound and 8 MiB cumulative registered-Intent bytes remain separately reviewable; removing them without proof would jeopardize control finality/lineage correctness. This compromise accepts bounded active memory over an ever-growing ordinary request cache. Real-native model behavior and efficiency remain UNVERIFIED until controlled trials.

### D26 / C18N-R — Correcting resource ownership without new Host autonomy

The fixed `maxCalls=32` in the actual registered External ToolPort was an independent cumulative quota that defeated the already accepted C18N ordinary MCP simplification; remove it rather than increase the threshold. Authorization, schema/input/output budgets and the durable observation owner remain independent of transport call-count identity. The preflight's repeated history/live scan is replaced with an invocation-borrowed technical identity/alias index and an Intent-sized temporary membership projection. This is *not* a second evidence store or a model-strategy filter; `admitFindings` can mutate only its temporary index. For live directory usability, expose `resumeCursor` even at the end of the current snapshot and name omitted large metadata (or report an explicit positional gap). External tool registration may use any valid built-in name because the existing bridge already assigns collision-free built-in aliases. No additional scheduler, semantic gate, mandatory retrieval, workspace check or action-count quota is justified by these corrections.
