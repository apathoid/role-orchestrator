# C08.1 — сопоставление ProviderPort и ACP v1

## Подтверждённая поверхность

- В lockfile зафиксированы `@agentclientprotocol/sdk@2.4.0` и `@agentclientprotocol/codex-acp@2.5.0`. Установленный CLI `codex-acp --version` подтвердил 2.5.0. Его собственная зависимость SDK имеет версию 2.1.0.
- Корневой импорт `@agentclientprotocol/sdk` в версии 2.4.0 предоставляет стабильный ACP v1, `PROTOCOL_VERSION === 1`. Подтверждены `client()`, `agent()`, `methods`, `ndJsonStream` и `ClientApp.connect`. Публичные вызовы идут через `connection.agent.request(...)` и `notify(...)`. Для двунаправленных сообщений SDK принимает WHATWG writable для исходящего потока и readable для входящего. `NdJsonStreamOptions.maxMessageBytes` ограничивает кадр. API `ClientSideConnection` и `AgentSideConnection` отсутствуют в этой версии.
- OBSERVED в `quality/tests/contracts/acp-v1-surface.test.js`. Стабильный клиент и управляемый агент через NDJSON обменялись initialize, session/new, session/prompt, session/update, session/request_permission, session/cancel и session/close. SDK подставил false для отсутствующих клиентских fs и terminal capabilities. Отдельный запуск установленного Codex ACP для рукопожатия не дал результата из-за отменённого согласования сетевого доступа в среде. Native ACP остаётся UNVERIFIED.

## Таблица соответствия

| Порт или событие | ACP v1 и SDK 2.4.0 | Граница реализации |
|---|---|---|
| Транспорт | JSON-RPC 2.0 по stdio, NDJSON, `client().connect(ndJsonStream(out, in, options))` | Адаптер владеет процессом и соединением, держит stderr отдельно. `connection.signal`, `closed`, `close()` относятся к соединению SDK. Завершение SDK и освобождение процесса проверяются отдельно. |
| Открытие и `describe` | `request(methods.agent.initialize, {protocolVersion, clientCapabilities, clientInfo?})` → `InitializeResponse` | Проверить согласованную версию. Объявлять клиентские capabilities по фактическим обработчикам. Считать возможности агента negotiated только после initialize. Справочный каталог может показать configured или unknown до соединения. Требуемую возможность проверять до prompt. |
| `open` и подготовка invocation | `session/new` с `cwd` и `mcpServers` → `sessionId`, необязательные `modes` и `configOptions` | `ProviderPort.open` получает профиль, а `cwd` приходит в Invocation. Нативную сессию с нужным cwd можно открыть при invoke до prompt. ACP требует абсолютный cwd; использовать рабочую директорию вызова или явно переданный доверенный default. Начальный список MCP пуст. Хранить раздельно локальный handle, ACP sessionId, operationId и attemptId. |
| Продолжение | `session/load` при `agentCapabilities.loadSession`; `session/resume` при `sessionCapabilities.resume` | `load` может воспроизводить историю через session/update; не относить её к новому attempt. `resume` не воспроизводит историю. Пока нет доверенной связи сессий, использовать новый ACP session и переданный контекст. `continuationReference` не даёт права выбрать ACP sessionId. |
| `invoke` | `session/prompt` с `sessionId` и `prompt: ContentBlock[]` | Text и resource link входят в базовый протокол. Image, audio и embedded resource требуют соответствующего `promptCapabilities` и реального источника данных. Адаптер не изобретает содержимое недоступного вложения. |
| Сообщения и инструменты | `session/update` с `sessionId` и `update.sessionUpdate`: `agent_message_chunk`, `tool_call`, `tool_call_update` | Принимать только по активной сессии и попытке. Сообщения модели и tool facts имеют разный provenance. `toolCallId` действует в пределах сессии. Статус tool и непрозрачный `rawOutput` не дают generic exit code. |
| Терминальный исход | `PromptResponse.stopReason`: `end_turn`, `max_tokens`, `max_turn_requests`, `refusal`, `cancelled` | Один коррелированный исход. `end_turn` допускает валидацию полного Decision. Исчерпание лимита, отказ и отмена остаются отдельными транспортными фактами. Разрыв после возможной отправки оставляет эффект unknown. |
| Расход | `usage_update` с `used`, `size` и необязательным накопленным `cost` | Использование контекстного окна и накопленная стоимость сессии не являются расходом попытки. При отсутствии измерения попытки usage остаётся unknown. |
| Разрешения | ClientApp `onRequest(methods.client.session.requestPermission)` получает `requestId`, `sessionId`, `toolCall` и `options`; ответ `outcome.selected` с `optionId` либо `outcome.cancelled` | Связать запрос с живой попыткой по сессии и JSON-RPC id, сохраняя различие числового и строкового id. Сохранять label и нативные варианты `allow_once`, `allow_always`, `reject_once`, `reject_always`. Текущий переносимый broker хранит allow/deny, поэтому отображение полной нативной семантики относится к C08.4. Не выводить standing authority из названия команды. |
| `cancel` | `notify(methods.agent.session.cancel, {sessionId})`; `stopReason: cancelled` приходит через исходный prompt, если агент подтвердил отмену | Уведомление не подтверждает прекращение. Ожидающие разрешения завершать как cancelled. Отмена запроса SDK через AbortSignal использует отдельный `$/cancel_request` и не заменяет отмену сессии. |
| `close` | `session/close` только при наличии capability `agentCapabilities.sessionCapabilities.close`. Иначе доступно закрытие принадлежащего адаптеру соединения и процесса. | Не удалять пользовательскую историю через `session/delete`. Подтверждать освобождение принадлежащих ресурсов. Допуск к новым сессиям зависит от проверенной политики соединения, а не от наличия какого-либо sessionId. |
| Внешний bridge | `fs/read_text_file`, `fs/write_text_file` и пять `terminal/*` методов из `CLIENT_METHODS` | Рекламировать только подключённые внешние операции. Для terminal `wait_for_exit` может вернуть явно наблюдаемые `exitCode` и `signal`. Нативные инструменты агента могут работать самостоятельно. |
| Настройки и модель | `session/set_config_option` после `configOptions`; категория `model` и подтверждённое текущее значение. `session/set_mode` относится к режимам. | Сверять нужное значение с доступными опциями. Неподдерживаемое значение даёт технический отказ. Нативные launch settings остаются локальными для адаптера. |
| Статус старой попытки | В стабильном v1 нет generic метода `lookupStatus(attemptId)`. | `session/list`, `session/load` и `session/resume` не подтверждают исход ранее отправленной попытки. |

Официальная спецификация: [транспорт](https://agentclientprotocol.com/protocol/v1/transports), [initialize](https://agentclientprotocol.com/protocol/v1/initialization), [сессии](https://agentclientprotocol.com/protocol/v1/session-setup), [prompt](https://agentclientprotocol.com/protocol/v1/prompt-turn), [tools и разрешения](https://agentclientprotocol.com/protocol/v1/tool-calls), [отмена](https://agentclientprotocol.com/protocol/v1/cancellation), [настройки сессии](https://agentclientprotocol.com/protocol/v1/session-config-options). Типы и runtime проверены по установленному пакету и его [публичному SDK](https://github.com/agentclientprotocol/typescript-sdk).

C08.2 реализует владельца соединения и нативной сессии. Эта проверка не подтверждает сессию модели или работу Zed.
