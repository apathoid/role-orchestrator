## Содержательная проверка

1. Read-only поручение не превращается в Host sandbox. Нативные permissions и границы гарантий описаны отдельно.
2. Нет обязательного Git root, HEAD/source fingerprint или автоматического drift transition.
3. Recovery ограничивает слепой replay конкретного unknown effect, сохраняя независимое продолжение.
4. Findings используются как рабочий модельный контекст; Host проверяет структуру/provenance, не актуальность или semantic sufficiency.
5. Роли/этапы разработки не становятся обязательным runtime workflow; прямой ответ и один профиль допустимы.
6. Single-writer/CAS относятся только к state оркестратора; parallel model invocations сохраняются.
7. Diagnostic sink отделён от durable truth; ошибку sink нельзя превращать в task failure.
8. Политики разработчика и tests расположены в development; runtime не читает их.
9. CLI cancel/inspect к живому владельцу имеют конкретный local control contract; не обещается межпроцессное управление без канала.
10. Capability unknown не является глобальным отказом; учитывается необходимость конкретной способности.
11. Generation/cursor относятся к собственному исполнению и не являются source epoch.
12. Истощение бюджета возвращает фактический progress, не Host-generated semantic verdict.

## Границы проверки

Ни один runtime acceptance сценарий ещё не выполнен. Полная работоспособность будущего кода, версии SDK, реальные настройки моделей, возможности ACP-клиента и доступ к провайдерам остаются предметом реализации и проверок соответствующих кластеров. Markdown validation не является доказательством native integration или business correctness.

Точные версии Node/зависимостей и protocol mapping устанавливаются по доступным официальным источникам при реализации C00/C07/C08. Это известная внешняя неопределённость, не скрытый пробел product architecture.
