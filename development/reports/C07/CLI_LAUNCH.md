# C07.1 — запуск Codex CLI

Исходный HEAD — `a21ea89f4f76dffb1b059535f6846eef826701b5`. Codex CLI выбран как первый исполнитель C07. Его бинарник версии 0.165.0 уже разрешается существующим npm lock через Codex ACP. Адаптер использует явно заданную команду и не зависит от расположения бинарника в этом пакете.

## Контракт

| Данные | Источник и передача |
|---|---|
| Executable | `launch.command` из доверенного конфига. Для прямого запуска это путь к Codex CLI или `codex` из настроенного PATH. |
| argv | Опциональный префикс `launch.args` для доверенной обёртки, затем `exec --json --skip-git-repo-check --model=<model> [--profile=<profile>] -`. Для прямого запуска префикс пуст. Обёртка должна передать оставшиеся аргументы, stdin и stdout без изменения. |
| stdin | UTF-8 текст подготовленного запроса. Владелец процесса пишет его в pipe и закрывает stdin. В argv и командной строке shell текста запроса нет. |
| stdout и stderr | stdout — JSONL событий Codex. stderr — отдельный поток диагностики. Формат JSONL относится к событиям транспорта. В C07.4 Controller должен вернуть полное JSON-решение в сообщении модели, которое проверит существующий decoder. |
| cwd | Переданная рабочая директория используется как cwd дочернего процесса. При её отсутствии действует обычное наследование cwd. Для Codex включён документированный `--skip-git-repo-check`. |
| Native settings | Модель берётся из выбранного доверенного профиля Role Orchestrator. Опциональный `nativeSettings.profile` выбирает профиль Codex. Нативные настройки разрешений определяются настройками Codex и выбранным профилем. |
| Environment | Наследуется окружение, переданное доверенной стороной. `launch.env` накладывает значения по ссылкам `fromEnv` на исходное окружение. Отсутствующая переменная даёт адресную ошибку до запуска. Значения предназначены для окружения дочернего процесса. |

Владелец правил запуска — CLI adapter. Он принимает декодированную конфигурацию и формирует данные для одного вызова `spawn` с `shell: false`. C07.1 не приобретает ресурсов процесса. Создание, потоки, таймаут, отмена и завершение дочернего процесса принадлежат C07.2. Протокол, код завершения процесса и код завершения инструмента разбираются на следующих шагах.

Источники — [официальная справка команд Codex](https://developers.openai.com/codex/cli/reference#codex-exec) и [неинтерактивный режим](https://developers.openai.com/codex/noninteractive).

## Проверка

- OBSERVED на Linux, Node 24.22.1. `node_modules/.bin/codex --version` вернул `codex-cli 0.165.0`. `codex exec --help` подтвердил stdin sentinel, JSONL, выбор модели и профиля, запуск вне Git.
- OBSERVED. В каталоге без Git запуск проверенного бинарника с аргументами `exec --json --skip-git-repo-check --model=configured-model --profile=operator -` и пустым stdin вернул код 1 и сообщение `No prompt provided via stdin.` Проверка завершилась до обращения к модели.
- OBSERVED. `codex-launch.test.js` запускает контролируемый дочерний процесс. Он получил точный argv, отдельный cwd с пробелами, сохранённое окружение и неизменный текст с shell-метасимволами и Unicode через stdin. Проверены отсутствующая ссылка на переменную и некорректные нативные настройки.
- UNVERIFIED — модельный ответ, JSONL реальной сессии, полномочия, отмена и завершение дерева процессов. Локальный Nix отсутствует.
