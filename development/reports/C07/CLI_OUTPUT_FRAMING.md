# C07.3 — JSONL и ограничение вывода CLI

Владелец процесса передаёт сырые stdout и stderr в буфер вывода адаптера. Для Codex CLI формат stdout задаётся флагом `exec --json`. Адаптер читает целые строки по LF, включая CRLF, и декодирует UTF-8 после сборки строки. На уровне фрейминга событие должно быть JSON-объектом с собственным непустым строковым `type`. Распознавание содержимого событий и проверка Decision относятся к C07.4. Обычный текст сообщения модели сохраняется внутри события.

Для одного вызова по умолчанию доступно 1 МиБ stdout, 64 КиБ stderr и 256 КиБ на отдельную JSONL-строку без LF. Это пределы адаптера на байты процесса. Они применяются независимо от бюджета истории. Адаптер возвращает удержанный префикс каждого потока, число полученных байтов и признак превышения бюджета. Stderr сохраняется отдельно как байты процесса.

Слишком большая или некорректная строка создаёт `PROTOCOL_ERROR` с причиной и позицией. Следующие строки разбираются в пределах оставшегося бюджета stdout. После исчерпания stdout уже принятые кадры доступны вместе с префиксом. Кадр, у которого отсутствует LF, остаётся только в префиксе. Повторные ошибки агрегируются по причине с количеством и номером первой строки. Диагностика содержит метаданные без текста вывода. Результат процесса передаётся отдельно.

Источник — [документированный вывод Codex exec](https://developers.openai.com/codex/noninteractive#make-output-machine-readable).

## Проверка

- OBSERVED. Вход подан по одному байту, включая разрывы внутри кириллицы, эмодзи и CRLF. События сохранены в исходном порядке. JSON-подобный stderr остался отдельным выводом.
- OBSERVED. Проверены неверный UTF-8, синтаксис JSON, форма события, выход с незавершённой строкой, повторные ошибки и кадр точно на границе. После слишком большой строки следующий кадр остаётся доступен.
- OBSERVED. При обрезке stdout точно перед LF синтаксически полный JSON ещё не считается кадром. Проверены точное число полученных байтов и независимое исчерпание лимита stderr.
- OBSERVED на Linux, Node 24.22.1. Тестовый дочерний процесс прошёл через контракт запуска и владельца процесса. Выход с кодом 6 сохранил корректное событие, часть следующей строки и stderr.
