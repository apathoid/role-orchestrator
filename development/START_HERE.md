# Начало реализации

**Текущий статус: спецификация, план и стартовая package/Nix/CI-инфраструктура. Production-код и бизнес-тесты ещё не написаны.**

Эта ветка предназначена для самостоятельной реализации нового Role Orchestrator. Не нужна никакая история другого проекта. Реализуй последовательно кластеры; каждый заканчивается работающим проверенным приращением, а не очередным планом будущей работы.

## Как исполнять план

Начни с C00. Для каждого шага прочитай входные контракты, реализуй указанный результат, добавь только осмысленные проверки поведения и соответствующие диагностические события. Затем выполни проверки шага. Не откладывай тестируемость и наблюдаемость до конца проекта.

Не спрашивай разрешения на каждое уже порученное изменение. Уточнение необходимо, если отсутствующее решение пользователя меняет внешние полномочия, обязательный продуктовый scope или необходимый реальный доступ. Не превращай неподтверждённые предположения в требования. Версии зависимостей и реальные SDK API проверяй по официальным источникам, записывай только существенные решения.

Если найден дефект, исправляй в слое-владельце. Нельзя вводить обёртку, fallback, скрытый retry или gate только ради зелёного теста. Ошибку документации исправляй согласованно с требованиями пользователя, сохраняя самостоятельность комплекта.

## Контрольные результаты сессии

В `STATUS.md` записывай последний завершённый шаг, следующий шаг, выполненные команды и ограничения. Подробные логи/находки помещай в `reports/<cluster-id>/` или `runs/<run-id>/`, а не в docs продукта. Не фиксируй скрытые рассуждения: достаточно решения, оснований и проверяемого результата.

Завершение шага требует выполненных критериев; наличие файла или компиляция сами по себе не заменяют бизнес-проверки. Недоступная native среда не мешает реализации независимых слоёв, но оставляет соответствующий acceptance UNVERIFIED. Не объявляй весь продукт готовым до закрытия обязательных проверок.

Разработка не должна останавливаться после C01/C02 как после «MVP». Цель плана — весь основной функционал до C12 включительно. Дополнительные будущие adapters не обязательны, если не нужны для двух реальных независимых исполнителей.
