# Инженерные качества разработчика

Этот набор применяется coding-агентом при реализации проекта. `kernel.md` — общие принципы; `decision-process.md` — порядок проверки значимых решений; остальные файлы — краткие напоминания и review-критерии.

Слова planning, implementation, review и final validation обозначают способы проверки разработчиком собственной работы. Они не требуют отдельных моделей и не определяют runtime workflow. Проектный AGENTS и текущие требования пользователя имеют приоритет. Существующие абстракции означают только уже реализованные части нового checkout.

Техническую архитектуру определяют самостоятельные документы продукта. Не переносить эти инструкции в runtime автоматически. Не использовать checkpoints как основание для новых host gates.
